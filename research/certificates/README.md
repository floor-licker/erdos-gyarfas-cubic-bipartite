# Full-range witness certificates

This directory is the shortest independent route to the computational
result. The authoritative bundle is
`eg58_witness_certificates.zip`:

- compressed size: 20,545,969 bytes;
- SHA-256:
  `721221d5d59ceafcb7cfc11ce704e49f17d34586529eb315d800fee6bb1b597e`;
- format: `EG58CER1`;
- theorem-supporting streams: 66;
- additional compatibility streams: 1;
- uncompressed stream bytes: 503,200,951.

The detached digest is in
`eg58_witness_certificates.zip.sha256`; per-member sizes, digests, counters,
and roles are in `eg58_witness_certificates.json`.

## Coverage

For side size \(v\), the incidence graph has order \(2v\). The bundle covers:

- the one available normalized root orbit at \(v=7\);
- both available root orbits at \(v=8\); and
- all three root orbits at every \(v=9,\ldots,29\).

Thus \(1+2+21\cdot3=66\) theorem-supporting streams cover every root orbit
used by the exhaustive search. Orbit 1 starts with
`{1,3,5}`, orbit 2 with `{1,3,7}`, and orbit 3 with `{1,7,8}`, after the
fixed rooted star `{0,1,2}`, `{0,3,4}`, `{0,5,6}`.

The compatibility member
`compatibility/v16-unreduced-c4-c8.cert` reproduces the earlier side-16
\(C_4/C_8\)-only certificate counters. It is a regression check and is not
needed for the order-58 theorem.

## What a stream proves

The checker reconstructs the root, restricted-growth state, ordered
candidate list, degree constraints, and pair-uniqueness constraints itself.
A structurally valid candidate has exactly one record:

- `0x08` plus three old-block indices: a Berge quadrilateral witnessing a
  newly closed \(C_8\);
- `0x10` plus an endpoint-pair code and seven old-block indices: a simple old
  length-14 path witnessing a newly closed \(C_{16}\); or
- `0x20`: expand the candidate and recursively verify its complete child
  subtree.

The checker deliberately does not trust:

- a production search executable;
- either production \(C_{16}\) cycle oracle;
- a stored negative assertion that no cycle exists;
- stored candidate blocks or partial configurations; or
- the counters in a stream header.

It regenerates those objects and reconciles the claimed counters only after
the stream has been consumed exactly. It rejects invalid witnesses, unknown
records, truncation, trailing data, inconsistent counters, and any expanded
branch that reaches a completed configuration.

## Verify or regenerate

From the repository root:

```sh
make verify-certificate
```

This compiles only `research/src/verify_eg_certificate.cpp`, verifies every
stream and digest, reconciles the result tables, and executes all checked-in
tamper cases.

To regenerate the deterministic ZIP from the certificate generator:

```sh
make generate-certificates
```

Generation is a stronger reproduction request and is not part of the
certificate checker's trust base.

## Remaining trust boundary

Accepted streams prove that every branch generated by the normalized
restricted-growth procedure closes. Coverage of all cubic bipartite
candidates additionally uses the mathematical root-stabilizer and
restricted-growth completeness proof, Proposition 10 in the paper. See
`research/docs/completeness_argument.md`.

The byte-level specification is in [`FORMAT.md`](FORMAT.md).
